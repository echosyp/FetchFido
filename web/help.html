Run your own FetchFido server

One container, one volume, no accounts. Your collars' positions stay on your own machine and never touch the hosted service.

1. Start it

With Podman (or Docker: the commands are identical with docker in place of podman):

podman run -d --name fetchfido --restart unless-stopped \
  -p 8080:8080 \
  -v fetchfido-data:/data \
  -e ACCESS_TOKEN='choose-a-long-secret' \
  quay.io/f0c8bbv93/fetchfido:latest

Then open http://127.0.0.1:8080 on that machine, or http://<its address>:8080 from a phone on the same network. Tap the no server badge in the header, enter the token, and the phone syncs everything it hears to the server from then on.

2. The access token

There are no accounts in this mode, so the token is all that stands between the server and anyone who can reach its port: every position your collars have ever reported, the CSV export, and the ability to upload or delete. Leave it out only on a network you trust completely; the server logs a warning when it is unset. It is one shared secret for the household, entered once per phone.

3. Settings

All optional, passed as -e NAME=value:

VariableDefaultWhat it does
ACCESS_TOKENnoneRequired from every client when set.
RETENTION_DAYS30Positions older than this are deleted. 0 keeps them forever.
AUTH_MODEsingleaccounts gives each person their own login and their own collars, the way the hosted version works.
REGISTRATIONopenAccounts mode: closed stops new sign-ups.
TLS_CERT_FILE, TLS_KEY_FILEnoneServe HTTPS directly; mount the files into the container.
LISTEN:8080Address inside the container. Change the -p mapping instead.

4. HTTPS, or not

Bluetooth, GPS and installing the app as a home-screen icon all need a secure page: https://, or http://127.0.0.1 on the same machine. The Network transport, which talks to a node over WiFi, needs the opposite: a plain http:// page, because a secure page may not fetch from an http address. Pick what you need. For HTTPS on a home network, a certificate the phones trust is required; a self-signed one that the phone has not been told to trust is not enough.

5. Updating

podman pull quay.io/f0c8bbv93/fetchfido:latest
podman stop fetchfido && podman rm fetchfido
# then the run command from step 1 again

Positions and settings live in the fetchfido-data volume and survive this. To see what the server is doing: podman logs -f fetchfido.

6. What is in the box

The image is 11 MB: one static Go binary and an empty /data, built FROM scratch. It runs as an unprivileged user, has no shell, and makes no outbound connections. The database is SQLite in the volume, so a backup is a copy of one file.

Prefer not to run anything? The hosted version at fetchfido.echosyp.workers.dev is the same app with accounts; only collars you mark are stored there.
